# Enraged Eggplant Monster Library 0.2.0

The first approved public release of the Enraged Eggplant monster package: 304 GURPS monster conversions with
original AI-generated portraits, transparent overhead tokens, and flat-top hex tokens.

Original GURPS conversion by Enraged Eggplant, from *Monsters* (May 11, 2024); adapted and republished with
permission. Released under [CC BY 4.0](../../licenses/CC-BY-4.0.txt) with mandatory originator credit.

## What is in the package

- 304 monster records, every one manually reviewed and marked `approved`.
- Statistics, traits, skills, attacks, ratings, threat tiers, encounter metadata, size, and provenance.
- Three images per record: portrait, transparent top-down token, and deterministic flat-top hex token.
- Structured originator credit on every record and every manifest source.

## Deferred enrichment: lair, treasure, and grappling

**This package ships monster statistics, attacks, ratings, encounter metadata, and art. Lair, treasure, and
grappling values are not included: the authorized source states none, and the package does not invent them.
These fields are present and null on every record. Grapple-style mechanics that the source does state
(constriction, binding, engulf) are carried as attacks with their full resolution.**

The full decision and its reasoning are in
[`review/policy/0.2.0-empty-field-policy.md`](../../review/policy/0.2.0-empty-field-policy.md). This is
deferral, not abandonment: a later version populates these fields if a source with real data becomes
available, and states its derivation method.

## Changes from the conversion draft

**Mechanics restored.** The conversion's attack parser only recognised paragraphs shaped
`Name (skill): damage`. Every ability the source stated as a GURPS power construction produced nothing, so a
large part of the corpus reached review missing a signature ability — the cockatrice had no petrification, the
remorhaz no heat aura, the purple worm no poison. 144 records gained restored or annotated mechanics: 9
hand-authored records that had no attacks at all (swarms, oozes, the assassin vine, the shrieker) and 135
whose special constructions were re-extracted from the source with their own resolution text, or annotated in
place with the rating inputs they were missing.

**Save-or-disable abilities now rate.** A petrifying gaze deals no damage, so it was never a creature's best
attack and contributed nothing: a cockatrice rated at the CER floor of 1. Those abilities are now scored
through the rating model's affliction term, which is deliberately independent of the damage comparison. Each
construction is priced by one lever — a Binding by its ST, everything else by the point cost the source states
for it, at the model's standard 1 per 5 points, halved when the ability costs fatigue. 82 records carry a
priced disabling ability. Point cost is used rather than the construction's enhancement percentages, because
summing those (+660% for a basilisk gaze) would rate a basilisk above a storm giant; the point cost is the
source's own measure and is printed in the document, so every score is checkable.

**Ratings recomputed.** Offense, protection, and CER are computed through the same code path the Dungeons on
Automatic application uses. The conversion baseline ceilinged the damage base before applying the damage-type
multiplier — which inflates odd dice counts — ignored ranged accuracy and auto-hit attacks, and priced no
disabling ability at all. 192 records' ratings changed as a result and 23 changed threat tier. Every record
records both the reviewed value and the baseline it replaced. The application re-derives all 304 ratings from
stats alone and reproduces them exactly; a smoke in that repository fails if the two ever drift.

**Encounter metadata derived.** The draft shipped `averageNumberAppearing: 1` and `wanderingWeight: 1` on all
304 records as placeholders. Both are now derived from the reviewed threat tier and creature class by a rule
stated in every record's `conversionNotes`. Swarms count as one creature. Ten records keep an appearing count
capped at two: their disabling ability is one the source states no point cost or Binding ST for, so the rating
still cannot see it.

**GCS totals adjudicated.** All 15 exact-identity library cost discrepancies are adjudicated against the
published GURPS cost tables: 14 adopt the native library value because the stated cost does not follow from
the construction the document itself writes down, and 1 preserves the author's zero-point treatment as a
deliberate convention. All 40 source-total reconciliation entries are classified and documented. Details in
[`review/reports/gcs-adjudication.md`](../../review/reports/gcs-adjudication.md).

## Known limitations

- **Not every special mechanic is priced.** Save-or-disable abilities now rate, but insubstantiality,
  possession without a stated cost, immunities, regeneration, spellcasting, psionics, swarm bodies, and
  extreme mobility remain invisible to the rating. 258 records carry at least one such mechanic. Rather than
  fold a guess into the number, each is named per record in
  [`review/reports/cer-audit.md`](../../review/reports/cer-audit.md).
- **33 records have no parsed DR and 25 no parsed FP**, because the source states them as `-` or as a
  conditional value ("20 vs. cold and fire") that the Typical Stats parse cannot reduce to one number. Missing
  values score as zero, so those protection ratings are floors.
- **Visual GCS verification has not been done.** No record claims it: `checks.gcsVisualPass` is `false` for
  all 304. Opening each `.gct` in the GCS desktop application to confirm the displayed ancestry total remains
  outstanding, and each affected record names its own `.gct`.
- **Art has not been inspected by eye.** Every asset is verified to exist, be square, be at least 1024px, and
  carry real alpha where required; whether it looks right for the creature is not automated.

## Verification

```bash
npm test && npm run review:verify
```

Review decisions live in `review/decisions.jsonl` as an append-only ledger, and the package regenerates from
them deterministically. See [`review/README.md`](../../review/README.md).
