# Enraged Eggplant Monster Library 0.3.1

Adds a reader-facing `description` field to the monster contract. Same 304 approved records, same statistics,
ratings, and art as 0.2.x; no mechanical change.

Original GURPS conversion by Enraged Eggplant, from *Monsters* (May 11, 2024); adapted and republished with
permission. Released under [CC BY 4.0](../../licenses/CC-BY-4.0.txt) with mandatory originator credit.

## Monster descriptions

**Monster descriptions are original Dungeons on Automatic prose, written from each record's own statistics
and art direction and licensed CC BY 4.0. They are not derived from the fan-conversion source, which states
none, and not from any SRD. Records without a description carry the field as null.**

All 304 records ship prose. Coverage is generated into
[`review/reports/description-coverage.md`](../../review/reports/description-coverage.md) so it cannot
overstate itself, and `npm run review:apply` refuses to write a record missing the field.

### Why authored rather than imported

The obvious way to fill this field was to import SRD description text with credit. Two findings ruled it out
as the first move:

- **The authorized source has no descriptions to carry.** Reading all 1,597 headings of the parsed source
  corpus: every paragraph is a point-costed GURPS build or the resolution text for a specific ability, and
  the ability text is already carried as attacks and traits. Nothing is withheld by shipping no description,
  because there is nothing there to ship.
- **SRD description text is not CC BY.** The 3.5 SRD has prose for essentially every creature here — 293 of
  the 304 records match its monster index by name — but that text is Open Game Content under OGL 1.0a.
  Importing it would make every record a mixed-licence artifact and cost consumers the uniform CC BY grant
  this package exists to offer. SRD 5.1 is CC BY, but its monster entries are stat blocks with no
  per-creature prose. An OGL side-car package remains available as a separate, clearly-bounded option.

### Contract

Each description is self-describing about who wrote it and under what terms:

```json
"description": {
  "text": "A tree that stands up and walks. Bark-skinned, several times the height of a man ...",
  "authorship": "doa_authored",
  "basis": ["record.stats.traits", "record.stats.attacks", "record.size"],
  "contentLicense": "cc_by_4_0",
  "contentLicenseUrl": "https://github.com/Zuljita/DungeonsOnAutomaticMonsters/blob/main/licenses/CC-BY-4.0.txt"
}
```

The description states its own authorship and licence rather than inheriting the record's, because the
record's licence describes the fan-conversion mechanics and the description's describes prose this project
wrote. Enraged Eggplant originator credit is unchanged and still travels with every record.

`basis` names what the prose was written from, and may only name project-owned material. There is no enum
value for SRD text and validation rejects one, so OGL prose cannot reach a CC BY field by accident.

The full decision is in
[`review/policy/description-policy.md`](../../review/policy/description-policy.md).

## Consumer notes

- `description` is present on every record, as the object or `null`. Read it as `record.description?.text`;
  no existence check is needed.
- The field is optional at the contract level, so packages released before it existed remain valid.
- No other field changed. A consumer that ignores `description` sees 0.3.1 as identical to 0.2.3.
